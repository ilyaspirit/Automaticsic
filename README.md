## Что это

Инструмент для повторяющихся действий, которые надоело делать руками. Описываешь последовательность шагов в редакторе, сохраняешь в файл `.asic` — дальше двойной клик по нему выполняет всю цепочку и закрывается. Правый клик → «Редактировать» открывает редактор.

Типичный сценарий: утром открыть браузер на нужной странице, поднять почту, свернуть мессенджер в трей, развернуть редактор на весь экран. Или наоборот — вечером всё это закрыть.

Программа сделана для личного пользования, без расчёта на широкое распространение. Исходники открыты — забирай и правь под себя.

## Возможности

**Десять типов шагов**

| Шаг | Что делает |
|---|---|
| Запуск программы | Запускает exe, ярлык или адрес вроде `steam://`, с аргументами; умеет переключаться на уже открытое окно |
| Закрытие программы | Мягко через `WM_CLOSE`, выходом как при выключении Windows или принудительно; умеет закрывать дочерние процессы |
| Командная строка | Выполняет команду cmd или PowerShell — в окне оболочки или без него, с проверкой кода возврата |
| Действие с окном | Развернуть, восстановить, на передний план, сменить монитор, свернуть в панель задач или в трей, показать |
| Горячая клавиша | Отправляет сочетание глобально или в конкретное окно |
| Основной монитор | Назначает выбранный экран основным |
| Обои рабочего стола | Ставит картинку с выбором размещения или заливает стол сплошным цветом; умеет запомнить прежние и вернуть их |
| Пауза | Задержка в миллисекундах |
| Копирование файла | Из одного места в другое, с созданием папки назначения |
| Яркость Stream Deck | Меняет яркость подсветки Stream Deck, от 0 до 100% |

**Что умеет сверх этого**

- **Командная строка.** Шаг работает в двух режимах. *В окне оболочки* — окно открывается и остаётся на экране, сценарий идёт дальше: так смотрят `ipconfig` и держат ssh-мост, который переживёт закрывшийся сценарий. *Без оболочки* — окна нет; по галке «Дождаться завершения» сценарий ждёт конца команды, и тогда ненулевой код возврата валит шаг и кладёт вывод в лог: так подключают сетевой диск или синхронизируют папку, зная, получилось ли. Многострочные команды работают как есть, экранировать ничего не нужно.

- **Выход, как при выключении Windows.** Отдельный способ закрытия для тех, кого крестик не берёт. Программа вправе перехватить крестик и спрятаться в трей — а на выключение системы спрятаться нельзя: она обязана выйти и прибрать за собой. Так закрывается, например, клиент VPN, у которого туннель нужно свернуть по-хорошему. Никого не убивает: не вышла — считается ошибкой шага. Дочерние процессы получают ту же просьбу, а не завершение.

- **Свернуть в трей — двумя способами.** Своего значка в трее за чужую программу создать нельзя, поэтому выбор за тобой. *Нажать на крестик* — просьба к самой программе: Telegram, INCY и прочие, кто умеет прятаться в трей, спрячутся, и клик по их значку вернёт окно. *Спрятать окно средствами Windows* — окно убирается мимо программы, и достать его можно только шагом «Показать свёрнутое окно».

- **Обои туда и обратно.** Галка «запомнить прежние обои» записывает, что стояло на столе до смены, — путь, способ размещения и цвет фона. Пункт «вернуть запомненные» возвращает это назад. Запомненное лежит в настройках программы, а не в сценарии, поэтому запомнить может один сценарий, а вернуть другой — хоть после перезагрузки.

- **Алиасы.** Шаг запуска даёт программе кличку, последующие шаги обращаются по ней и попадают именно в то окно, которое запустили, — даже если открыто пять окон Chrome.

- **Аргументы и ярлыки.** Выбранный ярлык раскладывается надвое: путь к программе и её аргументы, оба видны и правятся.

- **Ярлыки Steam и прочие адреса.** Интернет-ярлык `.url` — внутри у него адрес вида `steam://rungameid/227300` — запускается как двойным кликом; адрес можно вписать и руками. Игру при этом открывает Steam, а не шаг, поэтому своего процесса у шага нет, и всё, что связано с окном, для таких ярлыков не применяется.

- **Работа от администратора.** Собранная программа просит повышение прав сразу при запуске: Windows не даёт управлять окнами и процессами, запущенными выше себя. Из исходников редактор стартует обычным; поднять его можно через **Параметры → Перезапустить от администратора**.

- **Запуск свёрнутым или на весь экран.** Пожелание, переданное при запуске, большинство программ игнорирует, поэтому нужное состояние окна дожимается после его появления.

- **Выбор монитора.** Поле «Монитор» есть у шага запуска и у действий с окном: отдельное действие «сменить монитор» только переносит, а у «развернуть», «восстановить» и «на передний план» монитор работает довеском — «развернуть» + «монитор 2» разворачивает на втором экране одним шагом. Окно переезжает так же, как по `Win+Shift+стрелка`: размер сохраняется, положение переносится пропорционально. Экраны нумеруются слева направо, «Основной» — отдельным пунктом. Кнопка «Определить» рядом со списком на пару секунд выводит номер прямо на каждый монитор.

- **Значки шагов.** Перед названием шага стоит значок программы, с которой он работает, — тот же, что показывает проводник. Найденный путь запоминается, поэтому значок виден и у закрытой программы. У шагов без программы значок системный. Тот же значок показывает и окно хода выполнения.

- **Форма не обещает лишнего.** Часть настроек в некоторых режимах не работает — например, ждать появления окна незачем, если ждать нечего. Такие галки и списки не просто гаснут: они показывают то, что произойдёт на самом деле. Твой выбор при этом сохраняется и возвращается вместе с режимом.

- **Запись сочетаний.** Поле, в котором нажимаешь нужное сочетание, и оно записывается, а не срабатывает. Ловятся и системные — `Alt+F4`, `Win+D`.

- **Шаги через буфер обмена.** `Ctrl+C` / `Ctrl+V` переносят шаг в том числе между окнами редактора и на другую машину: в буфер кладётся читаемый JSON. `Ctrl+D` дублирует шаг, `Del` удаляет.

- **Stream Deck без программы Elgato.** Устройство — обычный HID, яркость ставится одним feature-отчётом. Разговариваем с ним через системные `hid.dll` и `cfgmgr32.dll`, без сторонних библиотек и без официального софта. Поддерживаются Original, Mini, XL, MK.2, Plus и Neo.

- **Окно хода выполнения.** При двойном клике по `.asic` в трее появляется значок, а над ним окно с текущим шагом и прогрессом. Фокус не забирает, чтобы не мешать самому сценарию. Кнопка «Прервать» есть и здесь, и в редакторе.

- **Устойчивость к чужим файлам.** Шаг неизвестного типа не ломает загрузку: он выключается, но сохраняется в файле без изменений.

## Установка

Нужен Python 3.12 (64-бит) и [uv](https://github.com/astral-sh/uv).

```
uv sync
```

Запуск из исходников:

```
uv run main.py                       пустой редактор
uv run main.py --edit файл.asic      открыть в редакторе
uv run main.py файл.asic             выполнить и выйти
```

## Сборка

```
uv run pyinstaller --noconfirm Automaticsic.spec
```

Готовый `dist\Automaticsic.exe` самодостаточен. Версия и значки берутся из проекта: номер — из `model.VERSION`, картинки — из `icon.ico` для самой программы и `icon_asic.ico` для файлов сценариев. Оба значка кладутся внутрь exe, отдельных файлов рядом не нужно.

Для отладки собирай с консолью, иначе трассировки уходят в никуда:

```
uv run pyinstaller --noconfirm --console Automaticsic.spec
```

Перед пересборкой закрой запущенный exe.

## Привязка файлов .asic

Из собранной программы: **Параметры → Переустановить ассоциацию**. Или вручную:

```
uv run install.py              установить
uv run install.py --uninstall  удалить
```

Всё пишется в `HKEY_CURRENT_USER\Software\Classes`, права администратора не нужны. Привязка держится на конкретном пути к exe: при переносе переустанови её. **Параметры → Проверить привязку .asic** покажет, что записано сейчас.

## Формат .asic

Обычный JSON, правится руками при желании.

```json
{
  "name": "Рабочее окружение",
  "autopause_ms": 200,
  "alias_exe": { "np": "C:\\Windows\\System32\\notepad.exe" },
  "steps": [
    {
      "id": "a1b2c3d4",
      "type": "launch",
      "enabled": true,
      "ignore_error": true,
      "comment": "открыть блокнот",
      "params": {
        "path": "C:\\Windows\\System32\\notepad.exe",
        "args": "",
        "show": "normal",
        "if_running": "skip",
        "wait_window": true,
        "wait_timeout_ms": 3000,
        "alias": "np"
      }
    }
  ]
}
```

| Поле шага | Смысл |
|---|---|
| `id` | Восемь символов, генерируется сам |
| `type` | `launch`, `close`, `command`, `window`, `pause`, `copy`, `hotkey`, `wallpaper`, `streamdeck`, `primary_monitor` |
| `enabled` | Выключенный шаг пропускается, но остаётся в файле |
| `ignore_error` | Ошибка записывается в лог, выполнение продолжается |
| `comment` | Примечание, дописывается к названию шага в списке |
| `params` | Параметры, свои у каждого типа |

Недостающие параметры подставляются значениями по умолчанию, поэтому старые файлы не ломаются при появлении новых полей. Устаревшие значения переводятся при чтении.

## Как устроено

Ядро — `model`, `actions`, `runner`, `winapi`, `streamdeck` — не знает про Qt: там модель шагов, обработчики действий и работа с Windows API. Интерфейс лежит отдельно: `editor`, `ui_props`, `ui_progress`, `ui_widgets`, `ui_style`.

Новый шаг — функция плюс строка в `actions.HANDLERS` плюс метод в `ui_props`. Типы шагов лежат группами в `model.STEP_GROUPS`, оттуда же берутся меню и список типов. Номер версии живёт в `model.VERSION`, сборка читает его сама.
